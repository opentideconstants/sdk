# SDK conformance suite

The suite that every OpenTideConstants SDK (Ruby, Python, TypeScript, C) must pass (SDK spec §7.1). Suite version **0.1** (it tests format major 0).

| Path | What it is |
|---|---|
| `api.json` | The API manifest: every public name, by its snake_case name (§7.1). |
| `name_fold.json` | The shared fold table for name search (§4.4.1). |
| `fixtures/` | Synthetic fixture releases, good and bad (CC0). See `fixtures/README.md`. |
| `cases/*.json` | The language-neutral cases. Generated by `tools/build_cases.py`; do not edit. |
| `cross/cross.json` | The cross-SDK cases (two runners in one case). Generated by `tools/build_cases.py`; do not edit. |
| `stream_index.py` | The reference builder of the stream index `index-v1.json` (spec §6.2), for the `assert_index` step. |
| `server.py` | The fixture HTTP server, the recording proxy and the tripwire. |
| `driver.py` | Runs the cases against one runner and reports PASS / FAIL / SKIP. |
| `runners/<lang>/` | One runner per SDK. `runners/null/` is the null runner. |

All Python here uses the standard library only (Python 3.10 or later).

```
uv run conformance/driver.py --runner "<runner command>"            # run every case
uv run conformance/driver.py --runner "<cmd>" --only '^search/'      # a subset (regular expression on the case id)
uv run conformance/driver.py --runner "<cmd>" --all-steps --report r.json
uv run conformance/driver.py --cross python="python conformance/runners/python/runner.py" \
    --cross ruby="ruby conformance/runners/ruby/runner.rb" --cross typescript="node conformance/runners/node/runner.mjs" \
    --cross c="c/build/otc_runner"                                   # the cross-SDK cases (C built with otc_fetch)
uv run conformance/driver.py --check-cases                           # lint the cases (cases/ and cross/)
uv run conformance/driver.py --selftest                              # check the fixture server and proxy
uv run conformance/tools/build_cases.py [--check]                    # regenerate the cases / check they are current
```

Exit status. The driver exits 0 only when at least one case ran and every case that ran passed. It exits 1 when a case failed, or when no case ran (an `--only` pattern that matches nothing, or a runner whose features make every case SKIP). It exits 2 for a usage error, a case file that cannot be loaded, a bad `--only` pattern, a runner that fails the handshake (the driver prints the tail of the runner's stderr), or a harness error. A harness error is an exception in the driver while it runs a case (for example a bad regular expression or a missing field in a driver step, or a server rule that is not valid): the case is reported as FAIL with the step index, and the run goes on to the next case. `--check-cases` exits 2 when it finds a problem. `--all-steps` keeps running a case after a failed step, so that every step is checked; the summary line counts the runner steps that were compared and that failed.

**The null runner** (`runners/null/runner.py`) answers every step with an empty result. It must fail every case. That is the RED proof of phase step S2. It fails each case at its first compared step, which is usually the open step. **The almost-right runner** (`runners/almost/runner.py`) answers `open` correctly for the open variants and every other op with an empty result; run with `--all-steps`, it shows that the later runner steps and the driver steps fail an SDK that opens and then does nothing. Every case must fail against it too.

**Profiles.** Some SDKs must have every feature, so a runner cannot pass by leaving one out. The driver takes the profile from the hello's `runner` name, or from `--profile`: `python`, `ruby` and `typescript` (Node) must claim `fs`, `fetch`, `json`, `eager` and `stream`; `typescript-browser` all but `fs`; `c` must claim `fs` and `stream`, `c-fetch` also `fetch`. A runner that lacks a required feature fails the handshake (exit 2). Other runner names (`null`, `almost`) have the profile `none`.

## How a run works

1. The driver starts the fixture server and the recording proxy on free ports on 127.0.0.1.
2. For each case it makes a new temporary directory, starts the runner, and reads the runner's hello line.
3. It sends the case's runner steps one at a time and compares each reply with the step's `expect`. Between runner steps it runs its own driver steps (server rules, file changes, request checks).
4. A case passes when every step passes. At the end the driver closes the runner's stdin; the runner then closes its client and exits.

The runner gets a clean environment: no `OPENTIDECONSTANTS_*` and no proxy variables; `HOME` (and `USERPROFILE`), `XDG_CACHE_HOME` and `LOCALAPPDATA` inside the case's temporary directory, so no default cache directory is shared between cases or with the real home directory; plus the case's `env`. The first runner start (the probe that reads the hello) gets the same isolation.

## The runner protocol

A runner is a small program in the SDK's own language. It may call **only the public API** of its SDK. It reads JSON requests from stdin, one per line, and writes one JSON reply per request to stdout, one per line. Anything else goes to stderr (the driver keeps the tail of stderr in its report).

**Hello.** The first line the runner writes, before it reads anything:

```json
{"hello": {"runner": "python", "version": "0.1.0", "features": ["fs", "fetch", "json", "eager", "stream"]}}
```

| Feature | Meaning |
|---|---|
| `fs` | It has a file system: `file:` opens, `cache_dir`, `download`. (Not in a browser.) |
| `fetch` | It has the network and cache module. (C only with `otc_fetch`.) |
| `json` | It reads `.json` and `.json.gz` files. (Not C, which reads `.jsonl` + `.meta.json`.) |
| `eager` | It has eager mode. (Not C.) |
| `stream` | It has stream mode. |

The driver skips a case whose `requires` names a feature that the runner lacks. A step's `expect_if_missing` gives the expectation when the runner lacks a feature; the case ends after that step. So C without `otc_fetch` must return `not_built`, and TypeScript in a browser must fail `download` with `unsupported`.

**Request.**

```json
{"case": "geo/near-antimeridian@jsonl", "step": 1, "op": "near", "args": {"lat": 0.0, "lon": 179.95, "radius_km": 50}}
```

`on` (optional) names a release that `hold_release` stored; the op then runs on that `Release` instead of the client's current release.

**Reply.** Either a result object or an error:

```json
{"ok": true, "result": {"station_ids": ["OTC-T-0007", "OTC-T-0008"], "distance_km": [5.559754011674749, 16.679262035030458]}}
{"ok": false, "error": {"code": "checksum_mismatch", "message": "...", "fields": {"file": "...", "expected": "...", "actual": "..."}}}
```

- `ok` must be a JSON boolean. With `ok: false`, `error` must be an object, and `fields`, when present, an object. Any other shape is a malformed reply and fails the step.
- A step with no `expect` (a set-up step) still fails the case when its reply is malformed or `ok: false`.
- `code` is the stable error code (§4.8). The runner catches the SDK's **base error class only** (`OpenTideConstants::Error`, `OpenTideConstantsError`) and reports its `.code`. Any other exception is a runner failure: report it with code `"uncaught:<ClassName>"`, which fails the case. In C, map `otc_status` to the code.
- `fields` holds the error's detail attributes, with their snake_case names: `url`, `status` (network), `file`, `expected`, `actual` (checksum_mismatch), `path` (file_exists, io). C fills them from `otc_error` (`http_status` is `status`).
- An op that only does something (`close`, `hold_release`) replies `{"ok": true, "result": {}}`.

### Argument rules

- Arguments are the API's snake_case names. A runner turns them into its language's form by the rules of §4.1 (keyword arguments, an options object, a C struct).
- An argument that is absent from `args` is not passed (the SDK's default applies). An argument given as JSON `null` is passed as nil / None / null.
- Values are passed through with their JSON type, so a case can pass a wrong type (for example `country: 5`) to test `invalid_argument`. C, where the type cannot be wrong, reports `invalid_argument` for such a step without calling the SDK.
- Ops that take `station_id` (and `set_id`, `name`) look the objects up through the public API first (`station(id)`, `station.constant_set(set_id)`, `set.constituent(name)`) and then call the operation on them. If the lookup finds nothing, the runner replies with the result for "nothing" (`null` or `[]`) as the op's encoding gives it.
- Times in arguments do not occur in suite 0.1.

## Result encodings

Every object is a JSON object with exactly these keys (the driver fails extra or missing keys inside a result value). A field that the file leaves out is `null`, unless the row says otherwise. Enum values are the schema strings; an enum value the SDK does not know is `"other"` (§7.3). Numbers are JSON numbers (print doubles with enough digits to round-trip). A C `NaN` or a missing count (`-1`) is `null`. **Times** (`created`, `record_span.start`, `record_span.end`) are ISO 8601 UTC strings, `YYYY-MM-DDTHH:MM:SSZ`.

| Object | Keys |
|---|---|
| Station | `station_id`, `name`, `country`, `lat`, `lon`, `type`, `kind`, `timezone`, `aliases` (`{system: [ids]}`, `{}` if none), `status`, `is_reference`, `is_subordinate`, `is_tide`, `is_current`, `recommended_set_id` (the `set_id` of `recommended_set`, or null) |
| Tombstone | `station_id`, `name`, `status`, `removed_in`, `removed_reason` |

## Cases

`cases/<group>.json` holds `{"suite_version", "group", "description", "cases": [...]}`. A case:

```json
{"id": "geo/near-antimeridian", "title": "...", "spec": "4.4, 6.3",
 "matrix": {"root": "good", "release": "20991231.2"},
 "requires": ["fs"], "env": {}, "timeout_s": 60,
 "steps": [
   {"op": "near", "args": {"lat": 0.0, "lon": 179.95, "radius_km": 50},
    "expect": {"station_ids": ["OTC-T-0007", "OTC-T-0008"], "distance_km": [5.559754011674749, 16.679262035030458], "tolerance": 1e-06}}
 ]}
```

- **`matrix`**: the driver runs the case once per open variant and puts an `open` step first. The variants are `@json`, `@json.gz` (eager), `@jsonl` (eager), `@jsonl-stream`, each opening `fixtures/<root>/OTC_<release><ext>` with `file:`, and `@server` (eager, `release` pinned, from the fixture server into a new cache; it needs `fs` and `fetch`, because it passes `cache_dir`). The open step expects `loaded_from` `file` (or `download`) and the datestamp, plus the case's `open_expect`.
- **`expect`**: the keys other than `error`, `error_fields` and `tolerance` must be keys of the result, with equal values. `tolerance` (default 1e-9) is the largest absolute difference allowed for every number in the step. Strings and ids must be exactly equal. `{"error": code}` expects an error with that code; `error_fields` checks the error's `fields`.
- **Matchers** may stand in for a value: `{"$contains": s}`, `{"$regex": re}`, `{"$type": "object" | "array" | "string" | "number" | "boolean" | "null"}`, `{"$len_min": n}`, `{"$all": [matchers]}`, `{"$any_of": [values or matchers]}` (at least one matches).
- **Placeholders** in args, expectations and driver steps: `${fixtures}` (the absolute path of `conformance/fixtures`), `${server}` (`http://127.0.0.1:<port>`), `${server_alias}` (`http://otc-fixture.invalid:<port>`: the fixture server under a name that does not resolve; only the recording proxy relays it), `${proxy}` (the recording proxy URL), `${tmp}` (the case's temporary directory), `${cache}` (`${tmp}/cache`).

### Driver steps

| Step | What it does |
|---|---|
| `server_rules` `{rules}` | Sets the fixture server's scripted rules (see `server.py`): `status` (404, 500, 429 with `Retry-After`, `times`), `short_body` (Content-Length larger than the body, then close), `truncate` (a consistent but short body), `slow` (body after `delay_s`), `file`, `json` (serve one value of a fixture JSON file). Every rule field is checked when the rules are set (and by `--check-cases`); a bad rule is a harness error. A rule that fails when a request comes (for example a JSON pointer that does not resolve) gets a 500, and the request log entry has an `error`. A `json` rule whose file is missing gets a 404. Cleared at the start of each case. |
| `server_stop` / `server_start` | Stops the server and closes its open (keep-alive) connections; a tripwire on the same port records any new connection, and a request that still reaches the server on an old connection is also a tripwire entry with no response. Restarted at the end of each case. |
| `clear_log` | Clears the server, tripwire and proxy logs. |
| `assert_requests` | Counts logged requests (a proxy entry for a failed upstream has status 502 and the reason in `error`): `source` (`server`, `proxy`, `tripwire`, `any`), `match` (regex on the path), `status`, `header` (`{name: regex}`; with `all: true` every request must match), `has_query`, then `count` / `min` / `max`, and `min_gap_s` between them. |
| `copy`, `write`, `delete`, `mkdir`, `corrupt` | File set-up. `corrupt` flips one bit of the byte at `offset`. |
| `assert_files` | `dir` has the names in `present`, not those in `absent`, exactly `exactly`; `no_tmp` = no `.tmp-*` file left. |
| `assert_sha256` | A file's SHA-256 equals (or with `negate`, differs from) a hex digest or another file's. |
| `assert_json` | A JSON file's top-level keys match. |
| `sleep` | Waits `s` seconds. |
| `restart_runner` | Stops the runner and starts a new process, with `env` added. Same temporary directory and cache. Not in cross-SDK cases. |
| `assert_index` | The `index-v1.json` at `path` equals, key for key, the index that `stream_index.py` builds from the `.jsonl` at `jsonl` for `datestamp` (only `by` is free). |
| `json_set` | Sets one value (`pointer`, RFC 6901) of the JSON file at `path` to `value`. |

### Cross-SDK cases

`cross/cross.json` holds the cases that need two SDKs (spec §5.4, §5.5, §6.2; phase step S4). Run them with `--cross NAME=COMMAND`, two or more times. A cross case has `roles` (`{role: [features]}`), and each runner step names its role with `as`. The driver runs the case once for each ordered assignment of different runners to the roles whose features they have, with the id `<case>[<writer>><reader>]`. So with four SDKs each case runs 12 times, and every SDK writes for, and reads from, every other SDK. All roles share the case's temporary directory and `${cache}`. A step whose `as` is a list sends the request to every listed role before it reads any reply, so they run at the same time (the lock case).

| Case | What it shows |
|---|---|
| `cross/cache-offline-stream` | The writer fills the cache in stream mode, and its `index-v1.json` equals the reference index. With the server stopped, the reader opens the cache offline (pinned and latest), verifies it and answers the queries; zero requests reach the server, the tripwire or the proxy. |
| `cross/cache-offline-eager` | The same, with the reader in eager mode on the cached `.jsonl`. |
| `cross/index-shared` | One entry of the writer's index is changed (still fresh). The reader's answer shows the change, and the file is not rewritten: the reader uses the other SDK's index. |
| `cross/index-stale`, `cross/index-other-version` | A wrong `jsonl_sha256` or another `index_version` makes the index stale: the reader ignores it and writes the reference index. |
| `cross/lock-contention` | Both runners open the same uncached release at once, with a slow `.jsonl`: the server sends it once, and no `.lock` or `.tmp-*` is left. |

## Choices this suite makes where the spec is silent

These are written into the cases. Change them here and in `tools/build_cases.py` together.

- Word-start rank (§4.4.1): the match starts right after a space in the normalised name. A query that is empty after trimming (`"   "`) is `invalid_argument`.
- `release.conventions` and `release.licences` are in file order. `station.validation` is in file order. `cached_releases` and `prune` return datestamps newest first.
- `update` with nothing newer returns `{updated: false, from: D, to: D}`.
- `attribution` with a null DOI: `https://data.opentideconstants.org/OTC_{datestamp}.json` replaces `doi:{doi}`. Entries are joined with `"; "`, and each is `{provider}: {attribution}` as the licence gives it.
- `user_agent` is added after one space: `opentideconstants-{lang}/{version} (+https://opentideconstants.org) {suffix}`.
- A body shorter than its `Content-Length` is a `network` error. A consistent but short response is `checksum_mismatch`.
- A reference that does not resolve is `invalid_release` at open time in stream mode too.
- The latest pointer is `OTC_latest-f0.json`; the SDK falls back to `OTC_latest.json` only on a 404.
- `timeout` is one number of seconds for both the connect and the read timeout.
- `subordinates_of` returns the subordinate stations ordered by `station_id` (§4.4 gives no order for it).
- A network failure is the `network` error, also with `on_network_error: raise` and an empty cache. `offline_unavailable` is only for offline use (`offline: true` or `OPENTIDECONSTANTS_OFFLINE`) with no usable cached release, and for `releases()` offline with no cached index. This follows §5.2 step 1 and step 5 and §4.3; the `offline_unavailable` row of §4.8 (and its `when` text in `api.json`) also names "a network failure with `:raise`", which the suite does not follow.
- Retries (§5.7): 3 attempts in all, so a request that always fails with a 5xx is sent exactly 3 times, with waits of 1 s and 2 s between them. The third backoff value in §5.7 (4 s) is never used.
- The release.files of a pinned download (`loaded_from` `download`, a pinned `release`) come from `OTC_{D}.sha256` alone, because a pinned download reads no pointer and no index (§5.2): the names and digests in that file; `url` and `size` are the true values or null. A download of latest takes all four from the pointer (§4.3.1).
- Latest from a root whose only release has an unsupported format major (`bad/format-major`) is `unsupported_format`.
- The proxy cases (`net/proxy-option`, `net/proxy-env`, `net/proxy-env-no-proxy-other-host`) use `${server_alias}`. Ruby's `Net::HTTP` never sends a loopback address through an environment proxy; a name that does not resolve tests the proxy handling of every SDK the same way, because the request can only succeed through the proxy. `net/no-proxy-env` still uses `127.0.0.1`, so for Ruby it cannot tell `NO_PROXY` from the loopback bypass.
