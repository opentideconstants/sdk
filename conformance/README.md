# SDK conformance suite

The suite that every OpenTideConstants SDK (Ruby, Python, TypeScript, C) must pass (SDK spec §7.1). Suite version **1.0** (it tests format 1.0, the first published format).

| Path | What it is |
|---|---|
| `api.json` | The API manifest: every public name, by its snake_case name (§7.1). `pending_port` lists, per language, the prediction names (prediction spec §5) that SDK does not have yet: its API check requires them to be absent, and every other name to be present. A port removes its language's names, and its profiles' `PENDING_FEATURES` in `driver.py`, in the change that adds them. |
| `name_fold.json` | The shared fold table for name search (§4.4.1). |
| `fixtures/` | Synthetic fixture releases, good and bad (CC0). See `fixtures/README.md`. |
| `schemas/` | Copies of the pinned format 1.0 and index 1.0 schemas (site repository commit and SHA-256 in `tools/build_fixtures.py`), so `build_fixtures.py --check` runs with no network (D25). |
| `cases/*.json` | The language-neutral cases. Generated by `tools/build_cases.py`; do not edit. |
| `cross/cross.json` | The cross-SDK cases (two runners in one case). Generated by `tools/build_cases.py`; do not edit. |
| `stream_index.py` | The reference builder of the stream index `index-v1.json` (spec §6.2), for the `assert_index` step. |
| `server.py` | The fixture HTTP server, the recording proxy and the tripwire. |
| `driver.py` | Runs the cases against one runner and reports PASS / FAIL / SKIP. |
| `runners/<lang>/` | One runner per SDK. `runners/null/` is the null runner. |
| `tools/check_supported_formats.py` | Checks each SDK's `supported-formats.json` (`python/`, `ruby/`, `js/`, `c/`; spec §7.4, §8.6): its `language`, its `version` (the package version; for `js/` the top-level `version` of `package.json`, read as JSON) and its `supported_format_version` (the SDK's `SUPPORTED_FORMAT_VERSION`, C `OTC_FORMAT_VERSION`). Every SDK must declare it with a quoted `MAJOR.MINOR` literal; an SDK that declares none, or declares different values, fails. `supported_format_version` must also equal `api.json` `constants.SUPPORTED_FORMAT_VERSION.value` (CR2 DR35). The declaration is read from every source file of the SDK (Python `.py` and `.pyi` with `ast`, where every binding of the name counts; Ruby `.rb`; TypeScript and JavaScript `.ts`, `.mts`, `.cts`, `.tsx`, `.js`, `.mjs`, `.cjs`; C every header and source). It fails closed: a binding whose value it cannot read (an unpacking, an import alias, a star import or `export *` from outside the SDK, `A, NAME = ...` on one line or across lines, `const A = 1, NAME = ...`, an object property, `const_set`, `remove_const`, `delete`, `#undef`, and the other forms in the script's docstring) fails. Python comments and docstrings do not count. For Ruby, TypeScript and C, comments are not parsed out: a declaration in a line comment (`#`, `//`) fails whatever its value, and one on its own line inside a multi-line comment counts as a declaration, so reword or delete a commented-out declaration. A broken link among the sources is a file that cannot be read. The script needs Python 3.10 or later; an older Python exits 2 and checks nothing. A file that cannot be read is a FAIL for its language, and the other languages are still checked. `tests/test_group_j.py` tests each rule. |

The driver, the server, the runners and most tools use the standard library only (Python 3.10 or later). The exceptions name their needs in their script header, so run them with `uv run`: `tools/build_fixtures.py` needs Python 3.12 or later, `jsonschema`, `rfc3339-validator` and `rfc3986-validator`; `tools/gen_fold_table.py` needs Python 3.14 (for Unicode 16.0.0); the self-tests in `tests/` need `pytest` and `jsonschema`.

```
uv run conformance/driver.py --runner "<runner command>"            # run every case
uv run conformance/driver.py --runner "<cmd>" --only '^search/'      # a subset (regular expression on the case id)
uv run conformance/driver.py --runner "<cmd>" --all-steps --report r.json
uv run conformance/driver.py --cross python="python conformance/runners/python/runner.py" \
    --cross ruby="ruby conformance/runners/ruby/runner.rb" --cross typescript="node conformance/runners/node/runner.mjs" \
    --cross c="c/build/otc_runner"                                   # the cross-SDK cases (C built with otc_fetch)
uv run conformance/driver.py --check-cases                           # lint the cases (cases/ and cross/)
uv run conformance/driver.py --selftest                              # check the fixture server and proxy
uv run conformance/tools/build_cases.py [--check]                    # regenerate the cases / check they are current
```

Exit status. The driver exits 0 only when at least one case ran and every case that ran passed. It exits 1 when a case failed, or when no case ran (an `--only` pattern that matches nothing, or a runner whose features make every case SKIP). It exits 2 for a usage error, a case file that cannot be loaded, a bad `--only` pattern, a runner that fails the handshake (the driver prints the tail of the runner's stderr), or a harness error. A harness error is an exception in the driver while it runs a case (for example a bad regular expression or a missing field in a driver step, or a server rule that is not valid): the case is reported as FAIL with the step index, and the run goes on to the next case. `--check-cases` exits 2 when it finds a problem. It also checks that every error code a case expects from an operation is in that operation's `errors` list in `api.json` (`--api FILE` names another manifest); `not_built` is allowed for any operation. `--all-steps` keeps running a case after a failed step, so that every step is checked; the summary line counts the runner steps that were compared and that failed.

**The null runner** (`runners/null/runner.py`) answers every step with an empty result. It must fail every case. That is the RED proof of phase step S2. It fails each case at its first compared step, which is usually the open step. **The almost-right runner** (`runners/almost/runner.py`) answers `open` correctly for the open variants and every other op with an empty result; run with `--all-steps`, it shows that the later runner steps and the driver steps fail an SDK that opens and then does nothing. Every case must fail against it too.

**Profiles.** Some SDKs must have every feature, so a runner cannot pass by leaving one out. The driver takes the profile from the hello's `runner` name, or from `--profile`: `python`, `ruby` and `typescript` (Node) must claim `fs`, `fetch`, `json`, `eager` and `stream`, and `python` and `typescript` also `https_proxy`; `typescript-browser` `fetch`, `json`, `eager` and `stream`; `c` must claim `fs`, `stream` and `require_checksum`, `c-fetch` also `fetch` and `https_proxy`. With prediction (prediction spec §6.5), `python`, `ruby`, `typescript` and `typescript-browser` also claim `predict`, `localtime_module` and `localtime`, and `c` and `c-fetch` those three and `tzdir_env` (the CI runs with the optional local-time dependency installed, and C on Linux and macOS). Four more profiles: `python-no-tz` (Python without `tzdata` on an image with no system database) and `ruby-no-tz` (Ruby without `tzinfo`), each the base features plus `predict` and `localtime_module`; `c-no-localtime` (C built with `-DOTC_WITH_LOCALTIME=OFF`, and C on Windows), the features of `c` plus `predict`; `c-no-predict` (C built with `-DOTC_WITH_PREDICT=OFF`), the features of `c` without any of the four. TypeScript has no profile without `localtime` (`Intl` is built in). A runner that lacks a required feature fails the handshake (exit 2). Other runner names (`null`, `almost`) have the profile `none`.

**Pending features.** `PENDING_FEATURES` in `driver.py` lists, per profile, the profile features its SDK does not have yet (today the prediction features of every profile, the driver's side of `api.json` `pending_port`). A pending feature is not required, and a runner that claims one fails the handshake (exit 2), so the port that adds it removes the entry in the same change, as it removes an `expected-failures.json` entry that passes.

## Expected failures

`expected-failures.json` lists the cases that are known to fail for a runner today: the RED baseline of cross-SDK behaviour rules that an SDK does not follow yet. Each entry is `{"case", "runners", "package", "reason"}`:

- `case` is an expanded case id (`load/bad-duplicate-station-id-jsonl`, `geo/near-limit-zero@json`, `cross/verified-doi-handoff[ruby>typescript]`) or an `fnmatch` pattern of ids (`load/bad-duplicate-station-id-*`; an exact id matches first, so a cross id's `[writer>reader]` needs no escape).
- `runners` are the runner names (the hello's `runner`: `python`, `ruby`, `typescript`, `typescript-browser`, `c`, `c-fetch`) the entry applies to; `cross` applies to a `--cross` run, whose ids name the runners (`[writer>reader]`, with the `--cross` names `python`, `ruby`, `typescript`, `c`).
- `package` names the fix package (the SDK lane) that owns the fix; `reason` says what the SDK does today.
- `step` (optional) is the index of the step where the case fails today. When it is given, a case whose first failure is at another step is `FAIL`.

A listed case that fails is reported as `XFAIL` and does not fail the run. A listed case that passes is reported as `XPASS` and fails the run (exit 1): the SDK now follows the rule, so its lane removes the entry in the same change. An entry covers a wrong answer only: a harness error, and a runner that crashes, hangs, breaks the protocol or exits non-zero, are `FAIL` even for a listed case. `--no-expected-failures` ignores the file and reports every failure as `FAIL` (to see a lane's RED cases); `--expected-failures FILE` reads another file (it must exist). `--check-cases` checks the file: known runner names, a package and a reason, a `step` that is a step index, no other field, and a pattern that names at least one case.

## How a run works

1. The driver starts the fixture server and the recording proxy on free ports on 127.0.0.1.
2. For each case it makes a new temporary directory, starts the runner, and reads the runner's hello line.
3. It sends the case's runner steps one at a time and compares each reply with the step's `expect`. Between runner steps it runs its own driver steps (server rules, file changes, request checks).
4. A case passes when every step passes. At the end the driver closes the runner's stdin; the runner then closes its client and exits. A runner that exits with a status other than 0 (for example because closing its client failed) fails the case.

The runner gets a clean environment: no `OPENTIDECONSTANTS_*` and no proxy variables; `HOME` (and `USERPROFILE`), `XDG_CACHE_HOME` and `LOCALAPPDATA` inside the case's temporary directory, so no default cache directory is shared between cases or with the real home directory; plus the case's `env`. The first runner start (the probe that reads the hello) gets the same isolation.

## The runner protocol

A runner is a small program in the SDK's own language. It may call **only the public API** of its SDK. It reads JSON requests from stdin, one per line, and writes one JSON reply per request to stdout, one per line. Anything else goes to stderr (the driver keeps the tail of stderr in its report).

**Hello.** The first line the runner writes, before it reads anything:

```json
{"hello": {"runner": "python", "version": "0.1.0", "features": ["fs", "fetch", "json", "eager", "stream"]}}
```

| Feature | Meaning |
|---|---|
| `fs` | It has a file system: `file:` opens, `cache_dir`, `download`. (Not in a browser.) |
| `fetch` | It has the network and cache module. (C only with `otc_fetch`.) |
| `json` | It reads `.json` and `.json.gz` files. (Not C, which reads `.jsonl` + `.meta.json`.) |
| `eager` | It has eager mode. (Not C.) |
| `stream` | It has stream mode. |
| `https_proxy` | It reaches a proxy over TLS (an `https://` proxy). Not Ruby: `Net::HTTP` speaks plain HTTP to every proxy, so Ruby refuses an `https://` proxy (CR2 DR39). |
| `require_checksum` | Its `open` takes `require_checksum` (a missing `OTC_{D}.sha256` is `checksum_mismatch`). C only: the `otc_open_options` field, for `otc_open_file` and for the open of the cached file in `otc_fetch_open` (CR2 DR34). |
| `predict` | Prediction is built (prediction spec §5): the prediction and astro ops. C only without `-DOTC_WITH_PREDICT=OFF`; a C build without it answers `not_built`. |
| `localtime_module` | The local-time module is built (`to_local`; C `otc_tz_*`). C only without `-DOTC_WITH_LOCALTIME=OFF` and not on Windows (there `not_built`). |
| `localtime` | Zone rules are usable at run time: Python has the system database or `tzdata`, Ruby has `tzinfo` (and `tzinfo-data` where the system has no database), C can read its zone directory. Without it, `to_local` is `local_time_unavailable`. |
| `tzdir_env` | C only: `otc_tz_open` reads the environment variable `TZDIR` (prediction spec §4.1). |

The driver skips a case whose `requires` names a feature that the runner lacks. A step's `expect_if_missing` gives the expectation when the runner lacks a feature; the case ends after that step. So C without `otc_fetch` must return `not_built`, and TypeScript in a browser must fail `download` with `unsupported`.

**Request.**

```json
{"case": "geo/near-antimeridian@jsonl", "step": 1, "op": "near", "args": {"lat": 0.0, "lon": 179.95, "radius_km": 50}}
```

`on` (optional) names a release that `hold_release` stored; the op then runs on that `Release` instead of the client's current release.

**Reply.** Either a result object or an error:

```json
{"ok": true, "result": {"station_ids": ["OTC-T-0007", "OTC-T-0008"], "distance_km": [5.559754011674749, 16.679262035030458]}}
{"ok": false, "error": {"code": "checksum_mismatch", "message": "...", "fields": {"file": "...", "expected": "...", "actual": "..."}}}
```

- `ok` must be a JSON boolean. With `ok: false`, `error` must be an object, and `fields`, when present, an object. Any other shape is a malformed reply and fails the step.
- A step with no `expect` (a set-up step) still fails the case when its reply is malformed or `ok: false`.
- `code` is the stable error code (§4.8). The runner catches the SDK's **base error class only** (`OpenTideConstants::Error`, `OpenTideConstantsError`) and reports its `.code`. Any other exception is a runner failure: report it with code `"uncaught:<ClassName>"`, which fails the case. In C, map `otc_status` to the code.
- `fields` holds the error's detail attributes, with their snake_case names: `url`, `status` (network), `file`, `expected`, `actual` (checksum_mismatch), `path` (file_exists, io), `removed` (cache: the datestamps that `prune` removed before the failure, CR2 DR18) and `tombstone` (station_removed; not C, which has no error object). C fills them from `otc_error` (`http_status` is `status`). The `cause` of an `io` error (`api.json`) is the underlying exception; runners do not encode it.
- An op that only does something (`close`, `hold_release`) replies `{"ok": true, "result": {}}`.

### Argument rules

- Arguments are the API's snake_case names. A runner turns them into its language's form by the rules of §4.1 (keyword arguments, an options object, a C struct).
- An argument that is absent from `args` is not passed (the SDK's default applies). An argument given as JSON `null` is passed as nil / None / null.
- Values are passed through with their JSON type, so a case can pass a wrong type (for example `country: 5`) to test `invalid_argument`. C, where the type cannot be wrong, reports `invalid_argument` for such a step without calling the SDK.
- Ops that take `station_id` (and `set_id`, `name`) look the objects up through the public API first (`station(id)`, `station.constant_set(set_id)`, `set.constituent(name)`) and then call the operation on them. If the lookup finds nothing, the runner replies with `null` as the op's value, also for an op whose value is a list (`subordinates_of`, `station_validation`, `constant_sets`, `constituents`, `set_validation`): an empty list would hide a lookup that fails.
- `reference_station` and `subordinates_of` (CR2 DR24): `station_id: null` is passed to the SDK as nil / None / null (C: `NULL`), not looked up; with `station_on` (the name of a held release) the runner looks the station up in that release and passes it to this one (a foreign Station). The lookup-fails-gives-null rule above applies only to a plain lookup.
- Times in arguments (`start`, `stop`, `times`, `at`; prediction only) are RFC 3339 strings in UTC, `YYYY-MM-DDTHH:MM:SS[.fff]Z`. The runner passes each as its language's instant (prediction spec §4.1): Python an aware `datetime` in UTC, Ruby a `Time`, TypeScript a `Date`, C `int64_t` seconds (C instants are whole seconds, so a fraction is only in cases that C does not run). A string with no zone designator (`2010-01-01T00:00:00`) is passed by the Python runner as a naive `datetime` (case `heights-naive-datetime`, Python only).
- Prediction ops take `station_id` and look the station up first, as above (the lookup-fails-gives-null rule applies). The astro ops (`equilibrium_argument`, `node_factor`, `equilibrium_for_year`, `node_factor_for_year`, `valid_range`) first call `release.astro_table(id)` (C `otc_astro_table`; `id` absent = no id) and then the function on the table they got; if `astro_table` gives none, the reply is `null` as the op's value. In C, when `otc_astro_table` returns `not_built`, the runner calls the function with a NULL handle and reports the function's status (prediction spec §6.5 `not-built/<function>`).
- `to_local` converts the result of the case's most recent prediction step (`heights`, `heights_at`, `extremes`, `currents`, `current_events`); a `to_local` step with no earlier prediction step is a runner failure. `tz` absent = no argument (the SDK's default, `"station"`). C opens the zone with `otc_tz_open` (the station's `timezone` from `otc_station_timezone` for `"station"`), converts each `t` with `otc_tz_local`, reads `tz_version` with `otc_tz_version` (null for `OTC_E_NOT_FOUND`) and closes it.
- `open` with `file` and any of `release` (other than `latest`), `offline: true` or `on_network_error` (other than `use_cache`) is `invalid_argument` (spec §4.2, CR D31). C has no client object (`otc_open_file` takes no fetch options), so the C runner applies this rule itself.

## Result encodings

Every object is a JSON object with exactly these keys (the driver fails extra or missing keys inside a result value). A field that the file leaves out is `null`, unless the row says otherwise. Enum values are the schema strings; an enum value the SDK does not know is `"other"` (§7.3). Numbers are JSON numbers (print doubles with enough digits to round-trip). A C `NaN` or a missing count (`-1`) is `null`. **Times** (`created`, `record_span.start`, `record_span.end`, `built_at`, `fetched_at`) are ISO 8601 UTC strings, `YYYY-MM-DDTHH:MM:SSZ`.

| Object | Keys |

## Cases

`cases/<group>.json` holds `{"suite_version", "group", "description", "cases": [...]}`. A case:

```json
{"id": "geo/near-antimeridian", "title": "...", "spec": "4.4, 6.3",
 "matrix": {"root": "good", "release": "20991231.2"},
 "requires": ["fs"], "env": {}, "timeout_s": 60,
 "steps": [
   {"op": "near", "args": {"lat": 0.0, "lon": 179.95, "radius_km": 50},
    "expect": {"station_ids": ["OTC-T-0007", "OTC-T-0008"], "distance_km": [5.559754011674749, 16.679262035030458], "tolerance": 1e-06}}
 ]}
```

- **`matrix`**: the driver runs the case once per open variant and puts an `open` step first. The variants are `@json`, `@json.gz` (eager), `@jsonl` (eager), `@jsonl-stream`, each opening `fixtures/<root>/OTC_<release><ext>` with `file:`, and `@server` (eager, `release` pinned, from the fixture server into a new cache; it needs `fs` and `fetch`, because it passes `cache_dir`). The open step expects `loaded_from` `file` (or `download`) and the datestamp, plus the case's `open_expect`. `matrix.open_args` adds open arguments to that step in every variant (for example `commercial_only`, K-NC DR106). A step `{"op": "open", "matrix_open": {args}}` opens the case's release again in the same variant, with `open_args` changed by the given arguments (a `null` removes one); in `@server` it expects `loaded_from` `cache`.
- **`expect`**: the keys other than `error`, `error_fields`, `error_message` and `tolerance` must be keys of the result, with equal values. `tolerance` (default 1e-9; a finite number of 0 or more) is the largest absolute difference allowed for every number in the step. Strings and ids must be exactly equal. `{"error": code}` expects an error with that code (or a matcher, such as `{"$any_of": ["io", "checksum_mismatch"]}`, where the spec allows more than one; `--check-cases` requires every listed code, and at least one code that each matcher matches, to be in the operation's `api.json` errors); `error_fields` checks the error's `fields`, and `error_message` (a value or a matcher) its `message`.
- **Matchers** may stand in for a value: `{"$contains": s}`, `{"$not_contains": s}` (a string without s), `{"$regex": re}`, `{"$type": "object" | "array" | "string" | "number" | "boolean" | "null"}`, `{"$len_min": n}`, `{"$all": [matchers]}`, `{"$any_of": [values or matchers]}` (at least one matches).
- **Placeholders** in args, expectations and driver steps: `${fixtures}` (the absolute path of `conformance/fixtures`), `${server}` (`http://127.0.0.1:<port>`), `${server_alias}` (`http://otc-fixture.invalid:<port>`: the fixture server under a name that does not resolve; only the recording proxy relays it), `${server_tls}` (`https://127.0.0.1:<port>`: the same fixtures over https, under a throw-away CA that the driver makes with the `openssl` command at start; a run without `openssl` is a harness error, exit 2), `${tls_ca}` (that CA's certificate file, for `ca_file`), `${proxy}` (the recording proxy URL), `${tmp}` (the case's temporary directory), `${cache}` (`${tmp}/cache`).

### Driver steps

The fields of every driver step are checked, by `--check-cases` and again when the step runs (`DRIVER_FIELDS` in `driver.py`): an unknown field (a typo such as `cuont`), a missing or wrong-typed field, an `assert_requests` `source` that is not one of the four logs, and an assertion step that asserts nothing (`assert_requests` with none of `count` / `min` / `max` / `min_gap_s` / `all`, `assert_files` with none of `present` / `absent` / `exactly` / `no_tmp`) are case-file errors: a harness error, never a pass.

| Step | What it does |
|---|---|
| `server_rules` `{rules}` | Sets the fixture server's scripted rules (see `server.py`): `status` (404, 500, 429 with `Retry-After`, `times`), `short_body` (Content-Length larger than the body, then close), `truncate` (a consistent but short body), `slow` (body after `delay_s`), `file` (with optional `headers`), `json` (serve one value of a fixture JSON file; `set` changes it at RFC 6901 pointers first). Every rule field is checked when the rules are set (and by `--check-cases`); a bad rule is a harness error. A rule that fails when a request comes (for example a JSON pointer that does not resolve) gets a 500, the request log entry has an `error`, and the case fails with a harness error. A `file` or `json` rule whose fixture file is missing, or outside `fixtures/`, is a bad rule; a fixture that goes missing after the rules are set gets a 500 and a harness error, never a plain 404. Cleared at the start of each case. |
| `server_stop` / `server_start` | Stops the server and closes its open (keep-alive) connections; a tripwire on the same port records any new connection, and a request that still reaches the server on an old connection is also a tripwire entry with no response. Restarted at the end of each case. |
| `clear_log` | Clears the server, tripwire and proxy logs. |
| `assert_requests` | Counts logged requests (a proxy entry for a failed upstream has status 502 and the reason in `error`; a request the recording proxy cannot relay fails the case with a harness error, so a 502 never passes as the SDK's network error): `source` (`server`, `proxy`, `tripwire`, `any`), `match` (regex on the path), `status`, `header` (`{name: regex}`; with `all: true` every request must match), `has_query`, then `count` / `min` / `max`, and `min_gap_s` between them. |
| `copy`, `write`, `delete`, `mkdir`, `corrupt` | File set-up. `corrupt` flips one bit of the byte at `offset`. |
| `assert_files` | `dir` has the names in `present`, not those in `absent`, exactly `exactly`; `no_tmp` = no `.tmp-*` file left. |
| `assert_sha256` | A file's SHA-256 equals (or with `negate`, differs from) a hex digest or another file's. |
| `assert_json` | A JSON file's top-level keys match (`match`); a key that starts with `/` is an RFC 6901 pointer into the file, for example to check that a `json_set` landed. |
| `sleep` | Waits `s` seconds. |
| `restart_runner` | Stops the runner and starts a new process, with `env` added. Same temporary directory and cache. Not in cross-SDK cases. |
| `assert_index` | The `index-v1.json` at `path` equals, key for key, the index that `stream_index.py` builds from the `.jsonl` at `jsonl` for `datestamp` (only `by` is free). |
| `json_set` | Sets one value (`pointer`, RFC 6901) of the JSON file at `path` to `value`. |
| `chmod` | Sets the POSIX permissions of `path` to `mode` (an octal string such as `"555"`). The driver gives the owner write permission back before it removes the case's temporary directory. |
| `assert_tree` | Every file and directory under `dir` (a relative path with `/`) matches one of the `allow` patterns (`fnmatch`, for example `["v1", "v1/**"]`). |

### Cross-SDK cases

`cross/cross.json` holds the cases that need two SDKs (spec §5.4, §5.5, §6.2; phase step S4). Run them with `--cross NAME=COMMAND`, two or more times. A cross case has `roles` (`{role: [features]}`), and each runner step names its role with `as`. The driver runs the case once for each ordered assignment of different runners to the roles whose features they have, with the id `<case>[<writer>><reader>]`. So with four SDKs each case runs 12 times, and every SDK writes for, and reads from, every other SDK. All roles share the case's temporary directory and `${cache}`. A step whose `as` is a list sends the request to every listed role before it reads any reply, so they run at the same time (the lock case).

| Case | What it shows |
|---|---|
| `cross/cache-offline-stream` | The writer fills the cache in stream mode, and its `index-v1.json` equals the reference index. With the server stopped, the reader opens the cache offline (pinned and latest), verifies it and answers the queries; zero requests reach the server, the tripwire or the proxy. |
| `cross/cache-offline-eager` | The same, with the reader in eager mode on the cached `.jsonl`. |
| `cross/index-shared` | One entry of the writer's index is changed (still fresh). The reader's answer shows the change, and the file is not rewritten: the reader uses the other SDK's index. |
| `cross/index-stale`, `cross/index-other-version` | A wrong `jsonl_sha256` or another `index_version` makes the index stale: the reader ignores it and writes the reference index. |
| `cross/lock-contention` | Both runners open the same uncached release at once, with a slow `.jsonl`: the server sends it once, and no `.lock` or `.tmp-*` is left. |
| `cross/index-station-id-swapped`, `cross/index-offset-past-eof`, `cross/index-datestamp-mismatch` | An index entry that names another station's line is `invalid_release` at the query; an entry out of bounds or another datestamp makes the index stale (rebuilt) (D4). |
| `cross/index-nul-name` | A station name with a NUL inside survives the writer's index and the reader's search. |
| `cross/verified-doi-handoff`, `cross/verified-doi-preserved` | The version DOI from the pointer reaches the other SDK through `.verified`, and an SDK that adds a file to the release keeps it (D26). |

## Choices this suite makes where the spec is silent

These are written into the cases. Change them here and in `tools/build_cases.py` together.

- Word-start rank (§4.4.1): the match starts right after a space in the normalised name. A query that is empty after trimming (`"   "`) is `invalid_argument`.
- `release.conventions` and `release.licences` are in file order. `station.validation` is in file order. `cached_releases` and `prune` return datestamps newest first.
- `update` with nothing newer returns `{updated: false, from: D, to: D}`.
- `attribution` with a null concept DOI (`good/` release `20991231`): `https://data.opentideconstants.org/OTC_{datestamp}.json` replaces `doi:{concept_doi}`. Entries are joined with `"; "`, and each is `{provider}: {attribution}` as the licence gives it.
- `zenodo_version_doi` is null for a file and for a pinned download (which reads no pointer), and after a download of `latest` it is the value of the entry the SDK used: the pointer's, or the index entry that step 2a chose. A cached release keeps it (`.verified`).
- `no_constants` sets: `constant_sets()` leaves them out by default and `include_no_constants: true` lists them; the `source` filter and `stats.source` do not count them; `stats.qc_status` counts every set.
- `provenance.build` is required in format 1.0, so every fixture set has it; the suite has no case for a missing one.
- `ConstantSet.time_base` is the set's annotation, or null (the model and official sets of the fixtures have none). `correction` is `{from, to}`; each `evidence` entry has its five keys, null when absent. The runners encode `correction` and `evidence` as the SDK returns them, so a missing key fails the exact-key check.
- A `qc_status` that format 1.0 does not have (`excluded` in `bad/format-minor`) is `other` (§7.3): `constant_sets()` lists it, `stats.qc_status` counts it under `other`, and `stats.source` does not count it (only `ok` and `flagged`).
- `bad/no-build` has a set with no `provenance.build` (malformed 1.0): it loads, and `build` is null.
- `reader_too_old`: the message must contain `1.99` (the fixtures' `min_reader_version`) and one other `1.x` version (the SDK's own `SUPPORTED_FORMAT_VERSION`).
- `stations/removed-error-tombstone` checks that `station_removed` carries the tombstone in `fields.tombstone`. Only Ruby, Python and TypeScript attach it (C has no error object), so the case requires `eager`, which C does not have.
- `user_agent` is added after one space: `opentideconstants-{lang}/{version} (+https://opentideconstants.org) {suffix}`.
- A body shorter than its `Content-Length` is a `network` error. A consistent but short response is `checksum_mismatch`.
- A reference that does not resolve is `invalid_release` at open time in stream mode too.
- The latest pointer is `OTC_latest-f1.json`; the SDK falls back to `OTC_latest.json` only on a 404.
- `timeout` is one number of seconds for both the connect and the read timeout.
- After `close` (CR2 DR32), `station_count`, `tombstone_count`, `constituent_names`, `conventions`, `convention`, `licences` and `licence` are queries, so they are `io`; the metadata getters that stay readable are the 8 keys of `release_metadata`, `citation` and `files`. `--check-cases` allows `io` for any op after a `close` step, by the `after_close` rule of `api.json`.
- `subordinates_of` returns the subordinate stations ordered by `station_id` (§4.4 gives no order for it).
- A network failure is the `network` error, also with `on_network_error: raise` and an empty cache. `offline_unavailable` is only for offline use (`offline: true` or `OPENTIDECONSTANTS_OFFLINE`) with no usable cached release, and for `releases()` offline with no cached index. This follows §5.2 step 1 and step 5 and §4.3; the `offline_unavailable` row of §4.8 also names "a network failure with `:raise`", which the suite does not follow (the `when` text in `api.json` agrees with the suite).
- Retries (§5.7): 3 attempts in all, so a request that always fails with a 5xx is sent exactly 3 times, with waits of 1 s and 2 s between them. The third backoff value in §5.7 (4 s) is never used.
- The release.files of a pinned download (`loaded_from` `download`, a pinned `release`) come from `OTC_{D}.sha256` alone, because a pinned download reads no pointer and no index (§5.2): the names and digests in that file; `url` and `size` are the true values or null. A download of latest takes all four from the pointer (§4.3.1).
- Latest from a root whose only release has an unsupported format major (`bad/format-major`) is `unsupported_format`.
- The shape of a 200 body (CR2 DR13, `rules/r2-pk06/`): a pointer is a JSON object with a `datestamp` and a `files` array, the index a JSON object with a `releases` array, and a `.sha256` file has at least one `<sha256>  <name>` row. A body of another shape is a `network` error, checked before the body is cached or compared with the pointer, so it never replaces the cached copy. A wrong value inside a body of the right shape (a bad datestamp, a file entry with no string `sha256` or no integer `size` of 0 or more, CR2 DR12) is `invalid_release`.
- The proxy cases (`net/proxy-option`, `net/proxy-env`, `net/proxy-env-no-proxy-other-host`) use `${server_alias}`. Ruby's `Net::HTTP` never sends a loopback address through an environment proxy; a name that does not resolve tests the proxy handling of every SDK the same way, because the request can only succeed through the proxy. `net/no-proxy-env` still uses `127.0.0.1`, so for Ruby it cannot tell `NO_PROXY` from the loopback bypass.
